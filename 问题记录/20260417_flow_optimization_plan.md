## 一、问题诊断

### 1.1 当前流程问题

| 问题 | 描述 | 影响 |
|------|------|------|
| 任务评估过于复杂 | 简单问题被判断为"复杂任务" | 增加延迟，用户体验差 |
| 多智能体模式臃肿 | 简单问题也走完整的多智能体流程 | 输出大量中间过程 |
| 中间过程污染答案 | 🚀 正在启动... 等内容被当作正式答案 | 界面混乱 |
| 类型丢失 | reasoning 类型数据处理不当 | 思考过程展示不正确 |

### 1.2 当前流程

```
用户输入 → 任务复杂度评估 → 单/多智能体选择 → 多智能体模式(固化流程) → SSE输出
                                    ↓
                              多智能体流程：
                              - 🚀 正在启动多智能体系统...
                              - 📋 任务分解中...
                              - ✅ 已分解为 X 个子任务
                              - ⚡ 并行执行子智能体...
                              - 🔄 合并结果中...
                              - 🎯 最终答案:
```

## 二、最佳实践对比

### 2.1 Claude Code 流程

```
用户输入 → 意图识别 → 规划(Planning) → 工具调用(Tool Use) → 结果整合 → 流式输出
```

**特点**：
- 轻量级评估，只判断是否需要工具
- 按需调用子智能体，不是固定流程
- 中间过程通过 Tool Call 展示，不污染最终答案
- 支持用户中断和干预

### 2.2 智谱 GLM、百问流程

```
用户输入 → Agent Loop → 工具执行 → 状态更新 → 流式输出
```

**特点**：
- Agent Loop 循环：思考 → 行动 → 观察
- 实时展示思考过程（不污染答案）
- 工具调用可视化
- 用户可随时干预

### 2.3 我们的差距

| 方面 | Claude Code/GLM | 我们 | 差距 |
|------|-----------------|------|------|
| 评估方式 | 轻量级意图识别 | 每次完整评估 | 延迟高 |
| 智能体模式 | 按需调用 | 固定流程 | 臃肿 |
| 思考展示 | 独立区域 | 混在答案中 | 混乱 |
| 用户干预 | 随时可干预 | 完成后才能看 | 体验差 |

## 三、优化方案

### 3.1 核心原则

1. **简单问题直接回答** - 不走复杂评估流程
2. **按需使用智能体** - 需要时才调用多智能体
3. **分离思考和答案** - 思考过程不污染最终答案
4. **用户可干预** - 支持中断和修正

### 3.2 优化后的流程

```
用户输入
    ↓
意图识别（轻量级）
    ↓
┌─────────────────────────────────────┐
│ 简单问题？                           │
│   是 → 直接调用模型 → 流式输出        │
│   否 → 进入 Agent Loop               │
└─────────────────────────────────────┘
    ↓
Agent Loop（仅复杂任务）
    ↓
┌─────────────────────────────────────┐
│ Loop:                               │
│   1. 思考（思考过程单独展示）         │
│   2. 规划下一步行动                   │
│   3. 执行工具（需要时）               │
│   4. 观察结果                         │
│   5. 判断是否完成                     │
└─────────────────────────────────────┘
    ↓
最终答案（干净输出）
```

### 3.3 具体修改

#### 3.3.1 简化任务评估

```python
# 当前：每次都完整评估
async def evaluate(self, user_message: str) -> TaskComplexityResult:
    # 1. 快速评估
    quick_assessment = self._quick_assess(user_message)
    # 2. 详细评估（耗时）
    detailed_assessment = await self._detailed_assess(user_message)
    # 3. 成本效益分析
    ...

# 优化：只做快速评估
async def evaluate(self, user_message: str) -> TaskComplexityResult:
    quick_assessment = self._quick_assess(user_message)
    if quick_assessment.is_simple and quick_assessment.confidence > 0.8:
        return TaskComplexityResult(mode="single", ...)
    # 复杂问题才进入 Agent Loop
    return TaskComplexityResult(mode="agent_loop", ...)
```

#### 3.3.2 移除多智能体固定流程

当前多智能体模式输出：
```
🚀 正在启动多智能体系统...
📋 任务分解中...
✅ 已分解为 X 个子任务:
⚡ 并行执行子智能体...
🔄 合并结果中...
🎯 最终答案:
```

**优化后**：只输出最终答案
```
🎯 最终答案:
[实际回答内容]
```

#### 3.3.3 思考过程独立展示

```javascript
// 前端处理
if (type === 'thinking') {
    // 思考过程单独区域，不计入答案
    thinkingContent += parsed.content;
    updateThinkingPanel(thinkingContent);  // 更新思考面板
}

if (type === 'answer') {
    // 正式答案
    answerContent = parsed.content;
    updateAnswerPanel(answerContent);  // 更新答案面板
}
```
