# 通用智能体框架工程基础设施完善方案

## 背景

MyPrivateAgent 作为通用智能体框架，核心智能体能力（执行循环、工具调用、MCP、Skill、Subagent、记忆系统、能力缺口治理）已基本完成。但工程基础设施存在明显短板，影响框架作为垂域智能体开发基座的可维护性和可靠性。

## 目标

补齐工程基础设施，使框架达到 MVP 成熟度，具备：
- 可追踪的数据库 schema 演进
- 可关联的请求链路追踪
- 可解析的结构化日志
- 统一的异常处理
- 基本的安全加固
- 基本的可观测性
- 可维护的代码质量

## 改进清单（18 项）

### P0 — 工程基础设施核心

1. **Alembic 数据库迁移** — 替代 create_all，支持 schema 版本化
2. **请求链路追踪** — X-Request-ID 中间件，贯穿日志和响应
3. **结构化日志** — JSON 格式日志，包含 request_id
4. **安全加固** — SECRET_KEY 默认值检测，CORS 白名单收紧
5. **统一异常处理** — 全局异常处理器，统一错误响应格式
6. **优雅停机** — lifespan shutdown 清理资源

### P1 — 可观测性与可靠性

7. **健康检查增强** — liveness + readiness 分离
8. **API 速率限制** — slowapi 基于 IP 限流
9. **上下文窗口管理** — token 计数 + 截断策略
10. **CI 流水线增强** — ruff + eslint 代码质量检查

### P2 — 代码质量

11. **重构超长函数** — orchestrator.py、chat_service.py
12. **前端流处理去重** — 提取 _processSSEStream
13. **后端流处理去重** — 提取事件处理管道
14. **消除硬编码配置** — 模型默认值移到配置层

### P3 — 框架成熟度

15. **启动配置校验** — bootstrap 阶段校验关键配置
16. **API 版本前缀** — /api/v1/ 前缀
17. **前端错误处理统一** — axios 拦截器统一处理
18. **测试覆盖率门禁** — pytest-cov 最低覆盖率

## 实施顺序

第一批（基础设施核心）：1→2→3→5→4→6
第二批（可观测性）：7→8→9→10
第三批（代码质量）：11→12→13→14
第四批（成熟度）：15→16→17→18

## 验收标准

- 每批完成后 smoke 脚本 + 前端构建 + 测试全部通过
- 所有改动不破坏现有 demo 功能
- 新增基础设施有对应测试覆盖
