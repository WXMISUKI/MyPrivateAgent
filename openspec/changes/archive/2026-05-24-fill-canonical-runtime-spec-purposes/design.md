# Design

## Boundary

This is documentation hygiene for canonical OpenSpec specs. It does not change behavior, API shape, runtime contract fields, or acceptance scenarios.

## Purpose Style

Each updated Purpose should:

- State the capability boundary in one short paragraph.
- Use the existing requirement body as the source of truth.
- Avoid restating implementation details, test names, or roadmap history.
- Avoid placeholder phrases such as `TBD`, `created by archiving`, or `Update Purpose`.

## Scope

The implementation updates the archive-generated placeholders found under `openspec/specs/`. No active changes are expected to remain after archive.

## Verification

OpenSpec strict validation is sufficient because this change does not modify code or requirement semantics.
